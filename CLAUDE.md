# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A content repository for publishing the same articles to both Zenn and Qiita. Articles are authored once in Zenn format and converted to Qiita format by a local script. Article content is written in Japanese.

- `articles/`, `books/` — Zenn sources (the layout `zenn-cli` and Zenn's GitHub integration expect). **This is the source of truth for new articles.**
- `public/` — Qiita articles (the layout `qiita-cli` expects). Files here are either generated by `ztoq` or pulled from Qiita by `qiita-cli`.
- `scripts/` — the Zenn → Qiita converter (`ztoq`), the only code in the repo.

## Commands

The package manager is in transition: `yarn.lock` is deleted in the working tree and `bun.lock` is untracked. Use `bun` unless told otherwise.

```sh
bun install

# Convert Zenn markdown to Qiita markdown (file or directory, recursive)
bun run ztoq <inputPath> <outputPath> [--watch]
bun run ztoq articles/my-article.md public/2025-B/      # output dir -> keeps basename
bun run ztoq articles public/2025-B --watch

# Previews
bunx zenn preview          # Zenn preview of articles/ and books/
bunx qiita preview         # Qiita preview of public/ (port 8888, see qiita.config.json)
bunx qiita pull            # sync public/ from Qiita
```

There are no tests, linter, or build step. `ztoq` runs through `ts-node` (CommonJS, `strict`); type-check with `bunx tsc --noEmit -p .`.

## Publish flow

1. Write or edit `articles/<slug>.md` with Zenn frontmatter.
2. Run `ztoq` to (re)generate the matching file under `public/`.
3. Commit both files and push to `master`.
4. Zenn picks up `articles/` via its GitHub integration. `.github/workflows/publish.yml` runs `increments/qiita-cli/actions/publish@v1` with `QIITA_TOKEN` to publish `public/`, and qiita-cli commits back the assigned `id` / `updated_at` ("Updated by qiita-cli" commits).

Because the workflow pushes commits to `master`, pull before making further changes after a publish.

The workflow's "Get published info" step and its `title` / `url` / `qiita_success` job outputs are placeholders — no job consumes them yet.

## Converter architecture (`scripts/`)

`scripts/ztoq.ts` is the CLI (yargs); it handles file-vs-directory input, recursion, and watch mode, and delegates all content transformation to `zennMarkdownToQiitaMarkdown` in `scripts/lib/`. That function is a simple ordered pipeline of `string -> string` transforms; add a new Zenn→Qiita syntax conversion by writing another transform and appending it to the `pipeline` array.

Current transforms, in order:

1. **`convertFrontmatter(outputPath)`**
   - Drops `emoji` and `type`; `published: true` becomes `private: false` (inverted).
   - `topics` are merged with any existing `tags` (case-insensitive dedupe) and written as Qiita tag objects (`- name: foo`). A `name@1.x` topic becomes `{ name, versions: ['1.x'] }`.
   - **Reads the existing output file** to carry over `id`, `updated_at`, and `organization_url_name`. These are assigned by Qiita; preserving them is what makes a re-conversion update the existing Qiita article instead of creating a duplicate. Never regenerate into a fresh path or delete the output file of an already-published article.
   - Other frontmatter keys (e.g. `slide`, `ignorePublish`) pass through unchanged, so Qiita-only keys can be set in the Zenn source.
2. **`replaceImagePaths`** — rewrites root-relative images (`![](/images/x.png)`) to `raw.githubusercontent.com/<owner>/<repo>/<branch>/...`, using `git remote origin` and the **currently checked-out branch**. Running `ztoq` on a non-`master` branch bakes that branch name into the URLs. Only matches images with empty alt text, and skips fenced code blocks. Silently no-ops if there is no git remote.
3. **`replaceMessageToNote`** — `:::message` → `:::note`.

## `public/` layout notes

- Hash-named files (`public/<20-hex-id>.md`) are articles pulled from Qiita; the filename is the Qiita article id.
- `public/2025-A/` currently holds a duplicate copy of those same hash-named files. `public/2025-B/` holds articles generated from `articles/` by `ztoq`.
- `public/.remote/` is qiita-cli's cache and is gitignored.
